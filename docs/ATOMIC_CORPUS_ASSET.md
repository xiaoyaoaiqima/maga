# 原子语料资产最小协议

## 目标

原子语料只解决三件事：可单独替换、可追踪实际选中项、可复现历史生成。

本阶段不新增数据库表，不引入标签兼容系统，也不改变 Prompt 展示内容。继续使用 `asset_registry` 管理资产版本、发布阶段、来源和哈希。

## 最小对象

`variation_slots[].options` 同时兼容旧字符串和结构化语料：

```json
{
  "slot_code": "consumer_recognition",
  "slot_name": "认可表达",
  "options": [
    {
      "id": "bf_001",
      "text": "看完这次活动和每批检测，对a2又多了点认可。"
    }
  ]
}
```

字段只有：

- `id`：在当前资产版本内稳定且唯一，用于追踪和问题定位。
- `text`：进入生成 Prompt 的原始语料。

语料角色由所在 slot 表达，不在每个 item 中重复保存。

## Planner 输出

Planner 将结构化语料还原成现有 `value`，保证 Renderer 和 Prompt 不变，同时在计划中记录 `item_id`：

```json
{
  "slot_code": "consumer_recognition",
  "slot_name": "认可表达",
  "value": "看完这次活动和每批检测，对a2又多了点认可。",
  "item_id": "bf_001"
}
```

旧字符串选项继续输出原结构，不补伪造 ID。

## 字段归属

以下信息不进入原子语料对象：

- 版本、状态、来源文件和来源哈希：归 `asset_registry` 资产版本。
- 适用路径和组合方式：归业务规则和 slot。
- “品牌感受原话”等 Prompt 标签：归 Renderer。
- 审核结论和发布记录：归评测及发布链路。

只有出现真实的固定搭配需求时，才单独设计显式组合关系；不能依赖数组下标，也不提前增加 `bundle_id`、兼容标签等字段。

## 渐进迁移

1. Planner 双读旧字符串和 `{id, text}`，生成行为保持不变。
2. 先迁移 a2 礼遇的认可表达候选资产，核对新旧 Prompt 等价。
3. 确认追踪记录稳定后，再决定是否迁移其他业务语料。

## 审核问题的语料溯源

审核发现正文异常时，先溯源该篇实际选中的原子语料，不先假定是模型自由扩写。

```text
正文问题
→ 查看 plan_json 中实际选中的 slot_code、item_id 和 value
→ 对照当前资产中的原子语料
→ 判断是源语料继承、模型扩写、审核遗漏还是后链路改写问题
→ 只在正确的层修正
```

如果问题表达能在实际选中的 `value` 中直接找到，默认先修语料资产；不为该句文案增加专用代码特判。只有同类模式在多条不同语料上重复出现，才考虑调整 Prompt 或审核规则。
