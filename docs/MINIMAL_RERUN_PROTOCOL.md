# 最小变量重跑协议

目标是证明某个具体改动改善了批次质量，而不是通过大范围提示词重写制造不可归因的变化。

## 流程

1. 保存基线：规则版本、素材版本、模型/参数、批次规模、生成与改写结果。
2. 选择一个故障层和一个最小变量，例如一条规则、一个示例槽位或一个 evaluator 条件。
3. 先 dry-run 或小批探针，确认没有破坏产品资格、合规和格式约束。
4. 在相同输入、模型、参数和样本范围下重跑。
5. 用同一评估矩阵做 before/after 对比，并保留失败样本。
6. 根据证据作出 `promote`、`watch`、`reject` 或继续收集证据的决定。

## 禁止事项

- 同一轮同时改多个规则层、模型和评估器。
- 只展示最佳样本，不报告整批分布和失败样本。
- 用单篇主观印象替代批次验证。
- 没有回归检查就把实验规则写入正式资产。
