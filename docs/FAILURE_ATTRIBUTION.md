# 内容质量失败归因

当产物不符合预期时，先定位故障层，再决定是否修改规则。禁止把所有问题都归因成“提示词不够好”。

## 六层归因

1. **source**：来源素材缺失、过时、噪声过大、授权范围不明或与目标场景不匹配。
2. **business rule**：业务规则、产品事实、活动口径、禁用词或示例本身冲突、过严、过宽或重复。
3. **context builder**：正确资产没有被加载、优先级错误、字段串位、上下文过长或规则层混合。
4. **generator**：模型、参数、路由、输出格式或生成链路导致的偏差。
5. **evaluator**：检查器漏检、误报、指标定义不清或人工标准没有结构化。
6. **rewrite**：改写阶段引入新问题、覆盖了原有有效信息或没有遵守业务边界。

## 判断顺序

```text
复现原始输入和真实链路
-> 核对 source / business rule
-> 查看 context snapshot
-> 对比 generator 原文与 rewrite 结果
-> 检查 evaluator 规则和人工反馈
-> 只选择一个最可能的故障层
```

每条归因都要绑定具体样本、字段或运行记录；不确定时标记为 `unconfirmed`，不要直接修改全局规则。
