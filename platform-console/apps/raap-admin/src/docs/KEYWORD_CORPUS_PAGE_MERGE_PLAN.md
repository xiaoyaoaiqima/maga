# 分类树 + 策略页面合并方案

**设计时间**: 2025-01-29 **目标**: 将分类树管理和策略配置合并为一个统一的关键词管理中心

---

## 一、现状分析

### 1.1 当前页面结构

**分类树页面** (`/keyword_corpus/category`)

- 📦 功能：管理分类树节点
- 🎯 用户：内容管理员
- ⚙️ 操作：创建/编辑/删除节点、添加关键词
- 📊 数据：直接操作 `nodes` 表

**策略配置页面** (`/keyword_corpus/strategy`)

- 📦 功能：配置内容生成策略
- 🎯 用户：运营人员、策略配置师
- ⚙️ 操作：选择节点、定义维度、配置组合
- 📊 数据：操作 `content_strategies` 表，引用 `nodes` 表

### 1.2 核心问题

| 问题           | 影响                                       |
| -------------- | ------------------------------------------ |
| **页面割裂**   | 创建节点 → 配置策略，需要切换页面          |
| **重复操作**   | 每次都要先去分类树创建节点，再回到策略配置 |
| **上下文丢失** | 切换页面后忘记刚才创建的节点               |
| **学习成本高** | 新手不知道两个页面的关系                   |
| **效率低下**   | 完成一个配置需要多次页面跳转               |

---

## 二、设计目标

### 2.1 核心原则

1. **渐进式披露** - 简单场景一键完成，复杂场景分步配置
2. **上下文保持** - 在一个页面完成所有操作
3. **灵活性** - 支持独立使用和集成使用
4. **向后兼容** - 保留原有功能，不破坏现有流程

### 2.3 目标用户

- **新手用户** - 向导式流程，逐步引导
- **熟练用户** - 快捷操作面板，一键完成
- **管理员** - 批量管理，数据维护

### 5.3 主页面结构

```vue
<!-- unified/index.vue -->
<script setup lang="ts">
import { ref, watch } from 'vue';
import { useRoute } from 'vue-router';

import NodesManagement from './components/NodesManagement.vue';
import StrategiesManagement from './components/StrategiesManagement.vue';
import QuickConfigWizard from './components/QuickConfigWizard.vue';

const route = useRoute();

// 从 query 参数获取当前 tab
const activeTab = ref('nodes');

// 监听路由变化
watch(
  () => route.query.tab,
  (tab) => {
    if (tab && ['nodes', 'strategies', 'wizard'].includes(tab as string)) {
      activeTab.value = tab as string;
    }
  },
  { immediate: true },
);
```
