# 关键词树 vs 关键词策略 - 架构关系说明

**文档时间**: 2025-01-29 **核心问题**: 既然有了关键词策略，还需要关键词树吗？

---

## 一、核心概念澄清

### 1.1 关键词树（Categories Tree）

**定义**: 层级化的节点组织结构，存储在 `nodes` 表中

**用途**:

- 📦 **数据存储层** - 存储所有关键词节点及其语料
- 🌳 **组织结构** - 按照分类层级组织（如：品牌 > 产品 > 型号）
- 🔍 **数据来源** - 为策略提供可选的节点池

**示例数据**:

```
nodes 表：
- id: 1001, label: "品牌", name: "Apple", corpus: [{"text": "苹果品牌"}]
- id: 1002, label: "产品", name: "iPhone", parent_id: 1001
- id: 1003, label: "产品", name: "iPad", parent_id: 1001
- id: 2001, label: "场景", name: "新品发布", corpus: [{"text": "新品上市发布"}]
- id: 3001, label: "卖点", name: "高性能", corpus: [{"text": "强劲性能"}]
```

**API 端点**:

- `GET /v1/keyword-corpus/categories/tree` - 获取分类树
- `POST /v1/keyword-corpus/categories` - 创建节点
- `PUT /v1/keyword-corpus/categories/{id}` - 更新节点
- `DELETE /v1/keyword-corpus/categories/{id}` - 删除节点

**管理页面**: `/keyword_corpus/category`

---

### 1.2 关键词策略（Content Strategy）

**定义**: 描述如何从关键词树中选择和组合节点的规则配置

**用途**:

- ⚙️ **配置层** - 定义内容生成的规则和组合方式
- 🎯 **选择逻辑** - 从关键词树中选择哪些节点
- 🎲 **组合规则** - 如何组合选中的节点

**示例配置**:

```json
{
  "strategy_name": "Apple 产品营销策略",
  "dimensions": [
    {
      "dimension_type": "品牌",
      "dimension_name": "品牌选择",
      "select_mode": "single",
      "node_ids": [1001], // 引用 nodes 表中的 Apple 节点
      "required": true
    },
    {
      "dimension_type": "产品",
      "dimension_name": "产品选择",
      "select_mode": "multi",
      "node_ids": [1002, 1003], // 引用 nodes 表中的 iPhone/iPad
      "required": true
    },
    {
      "dimension_type": "场景",
      "dimension_name": "营销场景",
      "select_mode": "single",
      "node_ids": [2001], // 引用 nodes 表中的场景
      "required": true
    },
    {
      "dimension_type": "卖点",
      "dimension_name": "核心卖点",
      "select_mode": "multi",
      "node_ids": [3001], // 引用 nodes 表中的卖点
      "required": false
    }
  ],
  "defined_combinations": [
    {
      "name": "iPhone 新品发布",
      "nodes": {
        "品牌": 1001,
        "产品": 1002,
        "场景": 2001,
        "卖点": 3001
      }
    }
  ]
}
```

**API 端点**:

- `GET /v1/keyword-corpus/content-strategies` - 获取策略列表
- `POST /v1/keyword-corpus/content-strategies` - 创建策略
- `PUT /v1/keyword-corpus/content-strategies/{id}` - 更新策略
- `DELETE /v1/keyword-corpus/content-strategies/{id}` - 删除策略

**管理页面**: `/keyword_corpus/strategy`

## 三、关键区别

| 维度 | 关键词树 | 关键词策略 |
| --- | --- | --- |
| **定位** | 数据存储层 | 配置层 |
| **作用** | 存储关键词节点及其语料 | 定义如何选择和组合节点 |
| **类比** | 食材仓库 | 菜谱 |
| **复用性** | 一个节点可被多个策略引用 | 一个策略可被多个 Expert 引用 |
| **维护方式** | 单独管理节点和语料 | 配置选择规则和组合方式 |
| **示例** | "Apple"、"iPhone"、"高性能" | "Apple 产品营销策略" = "Apple" + "iPhone" + "高性能" |

---

## 四、为什么两个都需要？

### 4.1 关键词树的必要性

#### 1. 数据复用

同一个节点可以被多个策略使用：

```
节点 "Apple" (id: 1001)
  ├─ 被 "Apple 手机营销策略" 引用
  ├─ 被 "Apple 平板营销策略" 引用
  └─ 被 "Apple 全产品推广策略" 引用
```

如果只有策略，每次都要重新定义 "Apple"，无法复用。

---

#### 2. 独立维护

节点和语料可以独立更新：

```
更新 "Apple" 节点的描述
  → 所有引用该节点的策略自动生效
  → 无需逐个修改策略
```

如果只有策略，修改一个节点需要更新所有相关策略。

---

#### 3. 数据管理

- 🔍 搜索和查找节点
- 📊 查看节点使用情况（哪些策略在使用）
- 🗑️ 删除前检查影响
- 📝 版本管理和审计日志

---

### 4.2 关键词策略的必要性

#### 1. 灵活组合

同一个策略可以定义不同的组合方式：

```
策略: "科技产品营销"
  维度 1 (品牌): Apple、华为、小米
  维度 2 (产品): 手机、平板、笔记本
  维度 3 (场景): 新品发布、促销活动
  维度 4 (卖点): 高性能、轻薄、长续航

  → 自动生成 3×3×2×3 = 54 种组合
```

如果只有关键词树，无法定义这种灵活的组合逻辑。

---

#### 2. 选择规则

策略可以定义复杂的选择规则：

```
维度 1: 必选，单选
维度 2: 必选，多选，最多选 3 个
维度 3: 可选，单选
维度 4: 可选，多选，全部选中
```

---

#### 3. 动态配置

- Scope 上下文（品牌级/产品级/全局）
- 筛选条件（按品牌/标签/产品筛选）
- 智能推荐（推荐热门节点）

## 五、类比说明

### 类比 1: 餐厅系统

**关键词树 = 食材仓库**

```
食材仓库:
  - 蔬菜区: 西红柿、鸡蛋、青菜
  - 肉类区: 猪肉、牛肉、鸡肉
  - 调料区: 盐、酱油、醋
```

**关键词策略 = 菜谱**

```
菜谱 1: 西红柿炒鸡蛋
  - 需要: 西红柿（1个）、鸡蛋（2个）、盐（适量）

菜谱 2: 青椒炒肉
  - 需要: 青椒（200g）、猪肉（300g）、酱油（1勺）
```

**Expert = 厨师**

```
厨师 A: 使用菜谱 1 做菜
厨师 B: 使用菜谱 2 做菜
```

**问题**: 如果取消食材仓库，每个菜谱都要自己种植西红柿、养鸡，合理吗？

---

### 类比 2: 代码系统

**关键词树 = 函数库**

```python
# 函数库
def add(a, b):
    return a + b

def multiply(a, b):
    return a * b

def divide(a, b):
    return a / b
```

**关键词策略 = 业务逻辑**

```python
# 业务逻辑 1: 计算订单总价
total = add(price, tax)

# 业务逻辑 2: 计算折扣价
discount = multiply(price, 0.8)
```

**Expert = 接口**

```python
# API 接口
@app.route("/order/calculate")
def calculate_order():
    # 使用业务逻辑 1
    pass
```

**问题**: 如果取消函数库，每个业务逻辑都要重新实现加法、乘法，合理吗？

## 六、新旧模式对比

### 6.1 旧模式: variable_mappings

**Expert 直接映射标签**

```json
{
  "expert_name": "手机营销 Expert",
  "variable_mappings": [
    {
      "variable_name": "写者",
      "label": "人设"
    },
    {
      "variable_name": "场景",
      "label": "场景"
    }
  ]
}
```

**问题**:

- ❌ 无法控制具体选择哪些节点
- ❌ 无法定义组合规则
- ❌ 无法预览组合效果
- ❌ 缺少灵活性

---

### 6.2 新模式: strategy

**Expert 引用策略**

```json
{
  "expert_name": "手机营销 Expert",
  "strategy_id": 12345
}
```

**策略定义选择规则**

```json
{
  "strategy_name": "手机营销策略",
  "dimensions": [
    {
      "dimension_type": "人设",
      "node_ids": [1001, 1002, 1003],
      "select_mode": "single"
    },
    {
      "dimension_type": "场景",
      "node_ids": [2001, 2002],
      "select_mode": "multi"
    }
  ],
  "defined_combinations": [
    {
      "name": "组合 1",
      "nodes": { "人设": 1001, "场景": 2001 }
    }
  ]
}
```

**优势**:

- ✅ 精确控制选择哪些节点
- ✅ 灵活定义组合规则
- ✅ 可以预览和测试
- ✅ 支持复杂业务场景

---

## 七、结论

### 7.1 关键词树仍然必需 ✅

**原因**:

1. **数据复用**: 一个节点被多个策略使用
2. **独立维护**: 节点和语料独立更新
3. **数据管理**: 搜索、查找、版本管理
4. **灵活性**: 支持多种策略选择

**如果取消关键词树**:

- ❌ 每个策略都要重新定义所有节点
- ❌ 节点更新需要修改所有相关策略
- ❌ 无法复用已有数据
- ❌ 维护成本暴增

---

### 7.2 关键词策略是进化的产物 ✅

**作用**:

1. **配置层**: 定义如何选择和组合节点
2. **灵活性**: 支持复杂的选择规则和组合逻辑
3. **可维护**: 策略配置独立于节点数据
4. **可扩展**: 未来可以支持更多高级功能

**如果取消关键词策略**:

- ❌ 回退到旧模式，灵活性降低
- ❌ 无法支持复杂业务场景
- ❌ 缺少组合规则和预览功能

---

### 7.3 最佳实践

**两个系统应该共存**:

```
关键词树（数据层）
  - 存储和管理节点
  - 提供搜索和筛选
  - 支持版本管理
        ↓
关键词策略（配置层）
  - 定义选择规则
  - 定义组合逻辑
  - 提供预览和测试
        ↓
Expert（应用层）
  - 引用策略
  - 配置 Prompt
  - 生成内容
```

## 八、常见问题

### Q1: 为什么不把节点直接存在策略里？

**A**: 因为节点需要复用。如果直接存在策略里：

- 同一个 "Apple" 要在 10 个策略中重复定义 10 次
- 修改 "Apple" 的描述要更新 10 个策略
- 无法统一管理和维护

---

### Q2: 关键词树会一直存在吗？

**A**: 会。关键词树是数据存储层，是系统的基础设施。策略只是配置层，定义如何使用这些数据。

就像：

- 函数库一直存在（关键词树）
- 业务逻辑会变化（策略）
- 接口会升级（Expert）

---

### Q3: 什么时候只需要关键词树？

**A**: 简单场景：

- 只需要选择一个固定的节点
- 不需要组合逻辑
- 不需要动态配置

例如：

- 简单的标签分类
- 静态的语料库
- 固定的模板

---

### Q4: 什么时候需要关键词策略？

**A**: 复杂场景：

- 需要从多个维度选择节点
- 需要定义组合规则
- 需要生成多种组合
- 需要灵活配置

例如：

- 营销活动配置（品牌×产品×场景×卖点）
- A/B 测试（不同组合方案）
- 个性化推荐（不同用户不同组合）

| 问题                   | 答案                                         |
| ---------------------- | -------------------------------------------- |
| 关键词树还有用吗？     | ✅ **有用**，是数据存储层，必需              |
| 策略能替代关键词树吗？ | ❌ **不能**，策略是配置层，依赖关键词树      |
| 两者关系是什么？       | **互补**，关键词树存储数据，策略定义如何使用 |
| 应该保留哪个？         | **两个都保留**，各司其职                     |
| 未来会怎样？           | 关键词树会演进，但不会消失                   |
