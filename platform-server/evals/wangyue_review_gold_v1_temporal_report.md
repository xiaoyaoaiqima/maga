## 目标问题

历史失败样本 `WYT-001`：

- 前文：“这段时间他好像特别容易中招，三天两头喉咙不舒服”
- 后文：“回看这段时间状态倒是挺稳”

两个相反的持续状态落在同一个时间窗口，中间没有“以前、前阵子、后来、换后”等阶段转换。人工金标为：

```json
{"label":"block","issue_code":"same_period_state_contradiction"}
```

## 2026-07-16 补充边界

本轮追加内容不改变首批 15 条，只补原规则未覆盖或未形成最小对照的时间问题：

- `WYT-016`：普通一顿饭没吃好后补充日常营养，不等于疾病症状后的即时补救，`pass`。
- `WYT-017/WYT-018`：短时间严重反转与有明确适应、观察跨度的对照。
- `WYT-019/WYT-020`：无过程多维度硬改善与有明确过程的对照。
- `WYT-021/WYT-022`：尚在决策与已经执行的阶段冲突及其正常写法。
- `WYT-023/WYT-024`：近期问题与已经饮用数月的跨度冲突及其正常写法。其中“前阵子”按距今 15-45 天理解，不能被解释成四个月前；四个月约 120 天，因此 `前阵子出现问题 -> 后来换奶 -> 已喝四个月` 必然冲突。
- `WYT-025/WYT-026`：长期持续饮用时，未解释与已解释的“以前/现在”基线对照。
- `WYT-001/WYT-027`：两处都写“这段时间”时，同期持续负面与整体稳定必须 block；把前文改成“前段时间”，和后文“现在/这段时间”形成明确前后阶段，可以 pass。
- `WYT-011/WYT-028`：`流感` 词本身由确定性硬禁词直接 ban；不含“流感”的“最近降温”等当前动态环境仍按独立发布时间锚点 block。
- `WYT-030/WYT-031`：产品使用时长必须覆盖被当作效果证据的历史事件；使用前事件作为负面基线可以保留，但不能反过来证明使用后的产品效果。

新增 block issue codes：

- `short_period_hard_reversal`
- `missing_transition_duration`
- `decision_execution_stage_conflict`
- `recent_problem_long_usage_conflict`
- `continuous_use_baseline_conflict`
- `pre_usage_effect_evidence`

时间词项目口径：

- `前阵子`：距今 15-45 天。
- 超过 45 天的旧阶段必须明确写成“几个月前、四个月前、上季度”等，不允许模型自行把“前阵子”扩展为数月前。
- `刚换/昨天换/才喝一两次 + 今天就/马上/一下 + 保护力稳住或产品生效`：明确表示产品在不超过一天或极短期内生效，固定判 `block / insufficient_effect_duration`，不设 watch 边界。

这里只统计现有时间专项检测器，不混入产品缺失、年龄、公共疾病等其他 guard。

| 红线召回率 | 16.7% |
| 非红线误拦率 | 0% |
| 可输出 watch | 否 |

当前检测器只稳定抓到“现在正是流感季”这类显式发布时间冲突；以下能力缺失：

- 同一时间窗口状态矛盾
- 单次小状况后立即用旺玥补救
- 刚换产品就承接长期效果
- 局部偶发状态与整体稳定之间的 watch 边界

## 候选 Judge

候选服务：`WangyueTemporalLogicJudgeService`

模型只输出：

```json
{"label":"pass|watch|block","issue_code":"枚举值","evidence":"原文证据"}
```

它不审核产品事实、违禁词、人味或种草，不提供改写建议，也不输出 `rewrite_required / severity / business_usability_tier / 主观评分`。
