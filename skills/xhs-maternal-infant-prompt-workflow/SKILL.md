# 小红书母婴提示词优化总入口

这是小红书母婴 UGC 语料和提示词工作的入口 skill。它不替代具体 skill，而是先判断任务类型、选择要联用的 skill、规定本地材料读取顺序，避免只用单一 skill 就开始改。

## 适用范围

- 小红书母婴内容：婴幼儿奶粉、宝宝喂养、转奶、奶量、便便、过敏相关、消化吸收、生长发育、容易生病、日常带娃观察、品牌种草。
- 用户说 `优化语料`、`改提示词`、`真人感`、`去 AI 味`、`太模板`、`同质化`、`品牌反馈`、`看这批问题`、`反哺规则` 时优先触发。
- 不适用于非母婴、成人消费品、教育、泛生活方式、医疗科普等场景。

## 路由规则

先判断用户要做哪类事，再联用对应 skill：

- 改 `产品使用体验`、月龄/周期/体验主题规则：使用 `product-experience-corpus-writer`，并联用 `prompt-corpus-loosener` 做真人感和去模板化。
- 改 `评论业务规则`、评论分类、楼中楼评论语料：使用本地 `comment-business-rule-corpus`；如果是在全局语料而非本项目语料，也可参考 `comment-business-rule-corpus-writer`。
- 只说 `这段不真人`、`太像 AI`、`太固定`、`帮我放松规则`：使用 `prompt-corpus-loosener`，并按本 skill 的本地材料顺序取样。
- 看文章池、生成 CSV、审核哪批有问题：使用 `xhs-maternal-infant-ugc-review`，再反哺到对应语料 skill。
- 需要找真实小红书表达、舆情、评论素材：使用 `xhs-social-intelligence`；不要直接把爬到的大段文本照搬进语料。

## 本地材料优先级

做真人感、品牌口径或规则修正时，优先读本地材料，再考虑外部搜索。

1. 品牌反馈文件，例如 `品牌反馈-0602-源悦ai评论-25条.xlsx`。
2. 已审核生文，例如 `批量生成/源悦-生文训练 - 常规0601-1-已审核.csv`。
3. 历史生成结果，例如 `批量生成/源悦-生文训练 - 常规0526-1.csv`、`源悦-生文训练 - 常规0529-1.csv`、最近的文章池导出。
4. 现有业务语料，例如 `关键词语料/产品使用体验_子关键词导出.csv`、评论业务规则语料。
5. 本地真实评论/舆情数据；只有本地材料不足时，再按相关 skill 做公开来源搜索。

引用本地材料时，优先抽取表达模式、品牌反馈边界和可复用口吻，不要生搬整句。

## 工作流程

1. 先说明将使用哪些 skill，以及为什么。
2. 读取当前任务相关的本地文件：品牌反馈、已审核问题、历史生成、目标语料。
3. 区分三类信息：
   - 品牌明确反馈：最高优先级，直接影响边界。
   - 历史通过/未被反馈的表达：可作为真人感和风格参考。
   - 模型生成问题：只能作为反面或待优化信号。
4. 再进入具体 skill：
   - `product-experience-corpus-writer` 负责业务 key 和语料块结构。
   - `prompt-corpus-loosener` 负责放松硬规则、降低模板味、保留真人感。
   - `comment-business-rule-corpus` 负责评论业务规则、楼中楼、短评论语料。
   - `xhs-maternal-infant-ugc-review` 负责文章池/CSV 审核。
5. 输出时给可直接替换的语料或规则，并说明它依据了哪些本地材料类型。

## 母婴通用口径

- 品牌种草文需要一定结果感和情绪张力；不要把 `满血复活`、`精神头贼好`、`没再蔫过`、`直接飙了2斤多` 这类生活化表达机械判错。
- 辅食可以作为 `7-12个月` 的日常喂养背景；只有当辅食被写成解决痛点的关键原因，或抢走当前体验主题时才判问题。
- 生长发育优先用本地品牌口径：`X个月X斤报道`、`脸圆/手厚/小腿有肉感`、`看着有点肉了`、`称重比上个月多了点`、`儿保/体检称重`。
- 月龄只作为后台业务约束，正文禁止写宝宝明确月龄；除非用户明确要求保留，否则删掉 `七个多月`、`半岁`、`七八个月那阵子`、`几个月宝宝` 这类表达。
- 产品使用体验语料里要放入通用规则：行为和细节注意符合宝宝阶段；正文可以按后台 `喝源悦时间` 写产品使用时长，例如 `不到俩月`、`转源悦几个月后`、`喝了大半年`。禁止的是宝宝明确月龄和 `宝宝几个月开始喝/从几个月喝到现在` 这类暴露月龄或制造冲突的组合。
- 时间词可以从用户或点点搜集稿里吸收，但要按后台使用时长分档：`3个月内` 可用 `刚喝不久`、`转奶第2周`、`喝了不到10天`、`尝试了一周多`、`喝了十几天`、`才喝半个月`、`这两周下来`、`差不多两个月整`、`喝了60多天`、`不到俩月`、`喝到第三个月`；`3-6个月` 可用 `转源悦第3个月`、`喝到第三个月`、`三四个月左右`、`喝了几个月`、`这几个月下来`、`喝了有一段时间`、`喝了小半年`、`快小半年`、`第5个月打卡`；`6个月以上` 可用 `喝了大半年`、`长期喝下来`、`半年真实反馈`、`喝了180多天`、`第6个月打卡`、`持续喝中`、`从第一次喝到现在`、`喝了挺久`。`入坑不到俩星期`、`源悦忠实用户第5个月`、`俩月测评` 这类测评腔可以改写成更生活化的使用时长，不直接高频复用。不要吸收 `从出生喝到现在4个月`、`从3个月喝到6个月`、`从1段转过来快3个月了` 这类暴露宝宝月龄、暗示阶段或容易制造冲突的表达；`这阵子`、`最近这一阵`、`最近这几天` 可以少量用，但同批不能变成最高频时间词。
- 产品使用体验参考素材要执行严格频控：以 `可参考素材` 条数为分母，时间词、生活场景词、情绪模板词和强场景组合的单项频率必须控制在 `5%` 以内。以 252 条参考素材为例，普通监控项最多 12 次；超过就继续改，不按“主题合理”放行。被用户点名偏高的词要设置更严上限，例如 `纸尿裤` 在参考素材和规则正文里都最高 3 次，不能靠换成一堆同义场景词来绕过同质化。核心主题词不做宽泛语义合并，但要拦组合复现，例如 `纸尿裤+小硬粒`、`睡前奶+220ml`、`辅食+奶`、`洗澡+小腿+称重`。修改后运行 `python3 scripts/check_product_experience_corpus_frequency.py` 做统一检查。
- 做词频降低或多样化时，固定流程是：先统计 `可参考素材`，再定普通上限和被点名词的更严上限，然后改“场景路径”而不是只做同义词替换；例如不要把 `纸尿裤` 批量换成 `尿不湿`，而要拆到 `拉的时候`、`擦屁屁`、`前后规律`、`小表情`、`换的时候顺手看` 等不同观察。改完必须同时查单词、同义替换词、强组合和真人感副作用；如果出现 `练抬头着练抬头`、`再喝完，喝完`、`奶这一顿像开盲盒` 这类机械连读或非真人表达，继续修，不能只因频控脚本通过就结束。被用户点名的新高频词要同步写入检查脚本的监控项或特殊上限。
- 频控不能只管 `可参考素材`，也要管规则正文。不要在提示 bullet 里写 `围绕纸尿裤、嗯嗯频率、软硬...` 这种固定场景列表；这种规则会把生成全部推向同一组词。便便、消化、奶量等主题的规则正文只写宽边界和合规红线，例如 `可以写日常观察和照顾感受，禁止写成治疗、调理或保证规律`，具体场景放进参考素材并做频控。
- 避免把 `抱起来有分量` 反复改写成 `胳膊酸`、`手臂酸`、`撑不住`；这类表达同批复现时按套路化处理。
- 真人感审核要拦内部归纳词和模型腔，例如 `奶能喝住`、`吸收感觉给力了点`、`个子肉都不咋长`、`称重有点动静`、`体重表不是一直卡着了`、`照顾起来顺很多`、`节奏还能接上` 这类不像家长自然会说的总结句；优先改成具体观察，如 `最近一顿能喝完`、`奶量没怎么掉`、`比上个月多了0.3kg`、`脸上看着有点肉`、`少追着喂几次`、`晚上没怎么闹`。
- 不要复用缺少真人来源的顺口改写，例如 `猜来猜去`、`围着这事儿猜`、`围着厕所这事猜`。这类表达不是本地真人示例，容易变成模型习惯；优先写具体动作或影响，如 `反复看几次`、`少被这事儿打乱`、`不用老盯着`、`擦屁屁时没那么费劲`。
- 喂奶表达要检查主语是否符合真人说法，禁止 `奶瓶没之前那么常剩`、`奶瓶剩得少` 这类主语错位句；可以写 `奶瓶里不怎么剩奶`、`剩奶没以前多`、`不用老倒奶`、`这顿能喝完`、`少分几次哄` 等具体观察，也可以少量用 `稳稳180ml`、`顿顿190ml干光光` 这种品牌种草里的情绪化数据表达，但同批不要反复复现 `瓶底不老剩一截`、`不用老盯刻度` 或同一套数字爽感句。
- 小红书自带 AI 助手或点点给出的优化稿，只吸收成参考素材和表达模式，例如 `转源悦`、`看奶瓶就焦虑`、`喝奶像开盲盒`、`老母亲松口气`、`稳稳180ml`；不要因此加重提示词，也不要让 `老母亲`、`松口气`、`安心一点` 变成每条都带的固定情绪收尾。单条语料参考素材超过 4 条时，复制同一个产品使用体验 key 拆成两条语料。
- 输出语料前要做形态去重：不要一批都写成 `之前偏瘦 + 喝了几个月 + 称重增加 + 妈妈安心`。如果是 `产品使用体验` 语料，多样性要体现在长文素材的叙事入口、生活场景、观察维度和素材颗粒度上，例如儿保称重、家人随口反馈、换奶前后喂养变化、日常穿抱观察、妈妈心态变化、品牌选择确认；同一组参考素材里不要每条都同时塞入使用周期、体重数字、外观变化和情绪总结，可以有短场景、半句吐槽、单一观察、数字报道、反预期过程等不同颗粒。不要改成一组评论业务规则短句。只有处理评论语料时，才使用 `同款`、`+1`、楼中楼接话等评论形态。
- 不要用自我解释式真人感句子，例如 `不是特别明显但当妈的会注意到`、`这种天天带的人最懂`、`细节骗不了人`；这类句子像在解释素材为什么成立。优先直接写观察本身，例如 `换衣服时发现袖口没那么空`、`摸着小腿没之前那么细`、`脸上没之前那么尖`。
- 不要随手发明不贴本地语料的观察，例如过度成人化的衣服细节；除非品牌反馈或历史通过样本里已有类似口径。
- 规则建议里不要写封闭白名单，例如 `只允许写...`；用 `禁止超龄动作 + 泛化边界`。

## 输出要求

- 对单段语料优化：直接给改后版本，少解释。
- 对批量审核：先给总体判断，再列高优先级问题，不要误伤品牌种草正常结果感。
- 对规则反哺：写成可直接放入语料的短句，避免长篇解释。
- 如果没有读取本地品牌反馈或历史样本，必须明说这是临时版本，不要假装已经参考本地口径。
