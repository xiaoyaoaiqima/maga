# 小红书评论批量 CSV 生成

用于快速生成“小红书评论区口吻”的母婴奶粉短评，并落成可导入的 CSV。默认场景是 A2/至初评论语料扩量，但方法可复用到其他评论业务规则。

## 默认输出

- 文件优先放到 `outputs/<topic>_<date>/`，不要覆盖已有批次。
- CSV 默认两列：`大类,评论内容`。
- 用户没有指定比例时，两类均分；例如 250 条写成 `有货` 125 条、`有货+转奶` 125 条。
- 如果用户明确说 Excel，但没有要求美化，优先问或默认快版：先出 CSV；必须 `.xlsx` 时只做数据表，不做排版预览。

## 生成方法

1. 锁核心事实，不扩展功效。
   - `有货`：只写有货、问货、调货、预留、先买到接上、线下/母婴店渠道。
   - `有货+转奶`：必须同时包含有货/调货和不转奶、暂停转奶、转回原奶粉、转奶麻烦或不顺。
   - 禁止新增宝宝状态变好、消化改善、长肉长高、品牌功效、检测报告细节，除非用户本轮明确给出。
2. 拆“评论动作”，每条只做一个小动作。
   - 报信：`我这边刚问到现货了`
   - 建议：`别只等线上，问问线下店`
   - 松口气：`终于不用看着空罐焦虑`
   - 不转奶：`能调到货我就不换了`
   - 转回：`试转不顺，刚好至初有货就回来了`
3. 换说话入口，而不是只做同义词替换。
   - 时间入口：早上/下午/这两天/刚刚。
   - 渠道入口：门店、母婴店、同城调货、本地群、熟人店。
   - 心理入口：松口气、不慌、先稳住、差点换。
   - 行动入口：留电话、登记、锁单、先买一罐。
4. 保持评论区真人感。
   - 用短句、不完整句、轻微情绪词和临场动作。
   - 不写品牌公告，不写整段解释，不把每条都写成完整种草文。
   - 避免同批高频复用同一组词，例如 `松口气/稳住/接上/不折腾`。

## 违禁词守卫

生成前必须复用 MAGA 业务违禁词台账，不另建散表。

- 后端真值：
  - `platform-server/app/services/business_forbidden_term_service.py`
  - `platform-server/app/services/forbidden_term_review_service.py`
- 默认 A2 评论资产：
  - `asset_key = a2_sentiment_comment_activity`
- 业务违禁词 entry 应包含：
  - `created_at`: 时间
  - `term`: 违禁词
  - `reason`: 违禁原因
  - `enabled`: 是否启用
  - 可选 `replacement/source/source_context/created_by`
- 已知首条：
  - `小程序`
  - 原因：`小红书不能出现微信生态的词`

如果服务/API可用，优先从接口拿当前启用词：

```http
GET /api/v1/content-generation/business-forbidden-terms?asset_key=a2_sentiment_comment_activity
```

如果本地服务不可用，至少读取本轮已知禁词和用户新增禁词，写入校验脚本参数。输出前必须扫禁词，不能只靠生成时提醒。

## 校验

写完 CSV 后运行验证脚本：

```bash
python3 skills/xhs-comment-batch-csv-generator/scripts/validate_comment_csv.py \
  --csv outputs/.../file.csv \
  --expected-total 250 \
  --category 有货=125 \
  --category '有货+转奶=125' \
  --forbidden 小程序 \
  --forbidden 微信
```

必须检查：

- CSV 可解析。
- 只有两列：`大类,评论内容`。
- 总行数和每类条数符合用户要求。
- 无空值、无坏分类。
- 评论内容无重复。
- 不命中启用违禁词。

发现问题时直接修 CSV 后复验，不要把有问题文件交给用户。
